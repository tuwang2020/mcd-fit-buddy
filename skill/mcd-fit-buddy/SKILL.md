# 麦麦瘦身助手（mcd-fit-buddy）

把「该吃哪一餐」从感觉变成**可计算的营养最优解**，并把「最近吃了多少」变成一张看得见的热量日历。

## 何时使用

- 用户想在麦当劳点餐，并关心**热量 / 健康 / 减脂**
- 用户想知道自己**最近在麦当劳吃了多少**、哪些天超标
- 用户想查附近门店、领券，随后要一份**健康方案**

## 可用工具（麦当劳 MCP Server `mcd-mcp`）

| Tool | 用途 |
| --- | --- |
| `order-list` | **历史订单**（热量审计的数据源，需过滤退款） |
| `query-nearby-stores` | 找门店，取 `storeCode`（得来速另取 `beCode`） |
| `auto-bind-coupons` / `query-store-coupons` | 领券、查本店可用券 |
| `query-meals` / `query-meal-detail` | 菜单、编码、组成、特调 |
| `calculate-price` | 真实计价（单位：**分**） |
| `create-order` / `query-order` | 下单（需用户确认）、查订单 |

## 标准工作流

### 链路 B：热量审计（用户问「我吃得健康吗」）

1. `order-list` 拉取历史订单；**过滤整单退款**；
2. 逐项匹配营养数据（代码或名称匹配；**查不到 → 标记「未知热量」，绝不估算**）；
3. 聚合：逐日热量、超标天数、平均每单、最高单日、高频单品、夜宵单数、含糖饮料份数、工作日 vs 周末差异；
4. 生成**热量日历**：终端文本版（`*` 标超标日）+ SVG 月历版（颜色档位按「当日热量/目标」）；
5. 结合用户身体指标（性别/年龄/身高/体重/活动水平）按 Mifflin-St Jeor 估算 BMR/TDEE，
   每日目标 = TDEE − 400 kcal（减脂，带安全下限），本餐目标 = 每日目标 ÷ 3。

### 链路 A：健康点餐（用户要「配一餐」）

1. 确认取餐方式与门店（`query-nearby-stores`）；
2. `auto-bind-coupons` + `query-store-coupons` 拿到**本店本单真正可用**的券；
3. `query-meals` 拉菜单并匹配营养；
4. **营养评分**（透明权重，可解释）：
   - 热量惩罚：`|本餐热量 − 目标| × 0.6`
   - 蛋白质加分：`蛋白质 g × 2`
   - 钠扣分：每超 700 mg 扣 0.05/mg；糖扣分：每超 17 g 扣 1.5/g
5. 组合规则：**1 主食 + 0~2 小食 + 0~1 饮料 + 0~1 甜品**；营养未知的餐品不参与；
6. **健康优先，其次比价**：只对已通过评分的方案跑用券最优化，**只在已选餐品内用券，绝不为了满减凑单**；
7. `calculate-price` 官方口径复核价格；
8. 输出：方案列表（每项含 kcal/蛋白质/钠/糖/实付）+ **每条推荐的理由** + **替换建议**；
9. 用户确认后才 `create-order`（到店需传 `takeWayCode`，取自 `calculate-price` 的 `takeWayList[].code`）。

## 输出格式约定

- 方案行：`· 餐品名 价格  热量`，合计行含 kcal / 蛋白质 / 钠 / 实付；
- 理用 `▸` 前缀逐条列出，必须包含「热量贴合度」与「钠/糖风险」；
- 替换建议格式：`原餐品 → 替代餐品，本餐少 X kcal`；
- 每次输出末尾注明：**输出为通用估算，不构成医疗建议；营养数据为公开标签近似值，以官方公示为准。**

## 参数传递硬规则（易错，务必遵守）

- 到店自取 `beType=1` → `orderType=1`，**不传** `beCode`
- 得来速 `beType=5` → `orderType=1`，**必传** `beCode`
- 麦乐送 `beType=2` → `orderType=2`，**必传** `beCode`
- 企业团餐 `beType=6` → `orderType=2`，**必传** `beCode`
- 所有价格为**分**；`storeCode` 必须全为数字

## 安全与合规

- 绝不输出、记录、上传用户的 Token、手机号等敏感信息；
- **不构成医疗建议**：孕产妇、慢病人群提示遵医嘱；不建议每日目标低于安全下限（女 1200 / 男 1500 kcal）；
- 营养数据为公开标签近似值，以官方公示为准；查不到的不要编。

## 降级策略

- MCP 不可用或未鉴权：提示检查连接器配置，并可用离线演示展示能力
  （`python -m src.mcd_fit.cli demo` / `calendar` / `advise`）；
- 营养库未收录的餐品：报告为「未知热量」，不影响其余餐品的审计与推荐。

更多工具字段与调用示例见 [`references/mcp-tools.md`](./references/mcp-tools.md)。
