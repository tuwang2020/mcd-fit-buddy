## 二次迭代：项目转向「麦麦瘦身助手」(mcd-fit-buddy)

**背景**：用户要求参考 `Ayzzz123/mcd-coupon-strategist`（麦麦省钱助手），把项目方向转为健康方向：
历史订单算热量 → 热量日历图 → 用户画像/饮食习惯 → 参考膳食指南推荐健康且能制造热量缺口的菜品 → 一键点单。

**从参考仓库提炼的可迁移经验**：双链路架构（单次决策 + 长期审计）、统一适配层（单位换算/字段映射/退款过滤）、
绝不编造数据（查不到记 0 并标注）、测试离线可跑、SKILL.md 置根 + mcp-config.example.json + docs。

**重构内容**（移除 `src/mcd_saver`，新建 `src/mcd_fit`）：
- `nutrition_db.py`：26 项麦当劳常见餐品营养参考库，查不到返回 None（宁缺毋滥）
- `body.py`：Mifflin-St Jeor BMR/TDEE、缺口 400 kcal、安全下限（F1200/M1500）、膳食指南常量（钠 2000mg/糖 50g）
- `auditor.py`：order-list → 逐单热量（退款过滤、未知热量单独计数）→ 7 类习惯洞察
- `calendar_render.py`：热量日历（终端文本 + GitHub contributions 风格 SVG，5 档颜色，浅色主题）
- `advisor.py`：★营养评分引擎（|kcal−目标|·0.6 + 蛋白·2 − 超钠·0.05 − 超糖·1.5，全可解释）+ 替换建议
- `pricing.py`：用券最优化，仅在已选餐品内用券（不为满减凑单）
- `adapter.py`：12 条实测调用契约（分/元、退款过滤、字段多形态、SSE、Mcp-Session-Id 等）
- 29 项单测全通过；demo 输出审计报告 + 双月热量日历 SVG + 3 个健康方案 + 替换建议

**关键决策**：目标函数从「实付最低」改为「营养最优，其次比价」——这个次序是本项目与省钱类工具的本质区别。
